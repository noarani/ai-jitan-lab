毎日の日報は、書く内容が決まっていないと、その日の出来事を思い出しながら文章を組み立てるだけで時間がかかります。読む側の上司も、長い文章の中から「結局、何が進んで、何が止まっているのか」を探すことになりがちです。

この記事では、メモをもとに日報の下書きを作るとき、ChatGPTには整理と短縮を任せる範囲で使う方法を扱います。例はすべて架空です。数字や成果の表現が事実どおりかの確認は、書く本人が行ってください。

## 日報にはどんな項目を入れますか？

**結論：やったこと、数字・進捗、うまくいかなかったことと原因の仮説、明日の予定、相談・報告したいことの5つに分けます。**

項目を先に決めておくと、メモを書く段階で「何を残すか」が迷いにくくなります。会社の指定様式がある場合は、その様式を優先し、下の5つは「メモを書くときの分け方」として使ってください。

架空の「法人向け営業の担当者」なら、次のように分けます。

1. 今日やったこと：訪問、提案資料の作成、見積の送付など、行動を事実として書く
2. 数字・進捗：件数、金額、期限に対する進み具合など、自分で確認できるもの
3. うまくいかなかったことと原因の仮説：「原因は〜かもしれない」と、仮説だと分かる書き方にする
4. 明日の予定：やることと、期限や時間が決まっているものを分ける
5. 相談・報告したいこと：上司の判断や確認が必要なことだけを取り出す

「原因の仮説」を事実と同じ書き方にしないことが大切です。原因が分かっていないのに断定すると、上司は誤った前提で判断することになります。

## ChatGPTへ渡す前に何を整えますか？

**結論：メモを5項目に分け、確認済みの数字と未確認のことを別に書き、入力してはいけない情報を外します。**

AIに渡す材料が、箇条書きの断片でも構いません。ただし、数字は「確認済み」と「うろ覚え」を混ぜないでください。うろ覚えの数字を確認済みと同じ書き方で渡すと、AIはそのまま文章に取り込みます。

Microsoftは、AIアシスタントへの依頼について、目的（Goal）、背景（Context）、使ってほしい情報（Source）、期待する返し方（Expectations）を含めるよう案内しています。 [Microsoft Support：Get started writing prompts in Microsoft Copilot](https://support.microsoft.com/en-us/microsoft-365-copilot/get-started-writing-prompts-in-microsoft-365-copilot) 日報でも、「日報にしたい」という目的だけでなく、誰が読むのか、どの形で返してほしいのかを添えると、返ってくる文章の方向がそろいやすくなります。

取引先名、個人名、未公開の売上や顧客の情報を含むメモは、原文のまま貼り付けません。個人情報保護委員会は、生成AIサービスに個人情報を入力する際、入力された個人情報が機械学習に利用されることがあるというリスクを踏まえて適切に判断するよう求めています。入力の可否は、勤務先の規程と利用するサービスの条件に沿って判断してください。 [個人情報保護委員会：生成AIサービスの利用に関する注意喚起等について（PDF）](https://www.ppc.go.jp/files/pdf/230602_alert_generative_AI_service.pdf)

入力前の確認項目は、[生成AIを安全に使うための入力前チェック](/ai-jitan-lab/anzen-gyomu-bunsho/seisei-ai-anzen-nyuryoku-mae-check/)でも扱っています。

## 日報のプロンプトはどう書きますか？

**結論：メモにあることだけを5項目に並べ、材料にない数字や評価の言葉を足さないよう依頼します。**

最初から「いい感じの日報にして」と頼むと、AIが成果を大きく見せる言い回しを足すことがあります。整理と短縮に役割を絞り、判断できない部分は`[要確認]`として残してもらいます。

次の例では、`[ ]`の中を、入力してよい範囲のメモに置き換えます。

```text
次のメモをもとに、上司に提出する日報の下書きを作成してください。

メモにない事実、数字、固有名詞、評価の言葉（「大幅に」「順調に」など）は追加しないでください。
数字はメモに書かれた表記のまま使い、計算や言い換えをしないでください。
原因は断定せず、「〜の可能性があります」と仮説の書き方にしてください。
判断できない内容は [要確認] と記載してください。
全体は読みやすい短さにまとめてください。

出力の形：
1. 今日やったこと（箇条書き）
2. 数字・進捗
3. うまくいかなかったことと原因の仮説
4. 明日の予定
5. 相談・報告したいこと（上司の判断が必要なものだけ）

【読む人】
[例：直属の上司。細かい経緯より、進み具合と相談事項を知りたい]

【今日やったこと】
[メモ]

【数字・進捗（確認済み）】
[メモ]

【うまくいかなかったこと】
[メモ]

【明日の予定】
[メモ]

【相談したいこと】
[メモ]
```

出力が返ってきたら、そのまま提出せず、次の確認に進みます。

## AIが盛った表現や、補った数字はどう見分けますか？

**結論：出力の数字と評価の言葉を、渡したメモと1つずつ照らし、メモに戻れないものは外すか自分で確かめます。**

もっともらしい文章でも、メモに根拠がなければ事実とは限りません。特に補われやすいのは、次のような部分です。

- 「前日比で改善」「大幅に進んだ」のような、比較や程度を表す言葉
- メモにない件数、金額、達成率
- 「問題なく完了」のような、状態を言い切る表現
- 原因を断定している文

確認するときは、出力の各行に印を付けると見直しやすくなります。

```text
[メモにある] 渡したメモに同じ内容がある
[足された] メモに見当たらない（外すか、自分で事実を確かめる）
[要確認] 数字の根拠や状況を、提出前に確かめる必要がある
```

Microsoftも、AIアシスタントの回答には不正確な内容が含まれることがあるとして、回答を確認し、必要に応じて信頼できる情報源と照らすよう案内しています。 [Microsoft Support：Get started writing prompts in Microsoft Copilot](https://support.microsoft.com/en-us/microsoft-365-copilot/get-started-writing-prompts-in-microsoft-365-copilot)

数字は、メモだけでなく、元の資料（見積書、管理表、メールなど）で見直すと安心です。文章を要約させて事実を確かめる手順は、[ChatGPTで要約した内容を事実確認する方法](/ai-jitan-lab/anzen-gyomu-bunsho/chatgpt-youyaku-jijitsu-kakunin/)でも扱っています。

## 上司が短い時間で読める並べ方は？

**結論：結論に近いものを上に置き、相談事項は目立つ位置にまとめ、経緯は短くします。**

日報は、上司が複数人分をまとめて読むことがあります。そのため、読み始めてすぐ「進み具合」と「判断が必要なこと」が分かる順にします。目安として、次の並べ方があります。

1. 相談・報告したいこと（判断が必要なものを先頭にまとめる。なければ「特になし」）
2. 数字・進捗
3. 今日やったこと
4. うまくいかなかったことと原因の仮説
5. 明日の予定

ただし、会社や上司によって、読みたい順番は異なります。上の順番は一例です。指定の様式がある場合はそれに合わせ、ない場合は、上司に「この並びで読みやすいか」を一度聞いてみる方法があります。

並べ替えたい場合は、プロンプトの「出力の形」の順番を書き換えるだけです。同じメモからでも、報告書など別の形式に展開できます。報告書の下書きについては、[ChatGPTで報告書の下書きを作る方法](/ai-jitan-lab/gyomu-jitan/chatgpt-hokokusho-sakusei-shitagaki/)で扱っています。

## まとめ：5項目に分けて渡し、数字と評価の言葉は自分で確かめる

ChatGPTで日報を書くときは、メモを「やったこと」「数字・進捗」「うまくいかなかったことと原因の仮説」「明日の予定」「相談」に分けて渡し、整理と短縮に役割を絞ります。メモにない数字や評価の言葉は`[足された]`や`[要確認]`として扱い、提出前に元の資料と照らしてください。

提出する内容の責任は書き手にあります。AIの出力は下書きとして使い、事実の確認は自分で行ってください。
