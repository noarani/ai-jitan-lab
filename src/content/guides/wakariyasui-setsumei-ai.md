説明したのに、相手から同じ質問が返ってくる。こういうとき、話し方だけを直そうとすると遠回りになります。先に見直したいのは、何を説明するのかと、相手が何を知っているのかです。

仕組みを話すのに手順だけを並べたり、新人に向ける説明を上司にもそのまま渡したりすると、内容が正しくても伝わりにくくなります。AIはたとえや図解のたたき台を作れますが、相手の仕事や数字の正しさまでは知りません。

この記事の例はすべて架空の小さな職場で、実在の企業や人物とは関係ありません。

## 説明する対象

まず、説明したいものに名前を付けます。混ざりやすいのは次の六つです。

| 説明したいもの | 相手が知りたいこと | 合う見せ方 |
| --- | --- | --- |
| 仕組み | 何がどこへ動くか | 図と矢印 |
| 手順 | 何から始めるか | 順番に並べる |
| 理由 | なぜその対応をするか | 具体例を一つ置く |
| 数字 | その数が何を意味するか | 身近な単位に言い換える |
| 比較 | 何がどう違うか | 表で比べる |
| 変更点 | 前と何が変わったか | BeforeとAfterを並べる |

たとえば、経費精算の新しい申請画面を説明するとします。画面を押す順番が分からない人には手順が必要です。承認が遅れる理由を聞く上司には、申請から承認までの流れと、変わる作業を見せたほうが早いです。同じ話題でも、説明する対象が違います。

## 相手の前提

次に、相手がどこまで知っているかを置きます。新人、他部署、上司は、同じ資料を見ても止まる場所が違います。

新人には、略語を使う前に言葉の意味と作業の順番を添えます。他部署には、その変更が自分たちの受け渡しにどう影響するかを示します。上司には、背景を長く話す前に、何を判断してほしいのかと、放置した場合の影響を短く渡します。

説明上手な人は、難しい言葉をたくさん知っている人とは限りません。相手がすでに知っている言葉から始め、知らない言葉を一度に増やさない人です。専門用語を外すだけで意味がずれるなら、言葉を消すのでなく短い補足を付けます。

## 見せ方の早見表

説明の形は、派手な図を作るために選ぶものではありません。相手がつまずく場所に合わせます。

| 相手がつまずく場面 | まず選ぶ見せ方 | 使い方 |
| --- | --- | --- |
| 全体の流れが見えない | 図と矢印 | 箱は三つ程度にし、矢印に動詞を書く |
| 作業の順番を迷う | 順番に並べる | 一番目から一つずつ書く |
| 二つの案を混同する | 表で比べる | 比べる項目をそろえる |
| 数字の重さが分からない | 数字の言い換え | 何件、何日、何人分かを添える |
| なぜ必要か納得しにくい | 具体例を一つ | 実際に起きそうな一場面だけを置く |
| 仕組みが抽象的 | たとえ | 合う部分と合わない部分を分ける |

たとえは便利ですが、説明そのものの代わりにはなりません。たとえば承認の流れを宅配便にたとえるなら、誰が荷物を受け取り、どこで止まるかは想像しやすくなります。一方で、実際の権限や締切まで宅配便と同じとは限りません。たとえの後に、本来の業務で何に当たるかを戻して説明します。

## AIに頼める下書き

AIには、説明の候補を増やす仕事を頼めます。たとえを一案だけ出させるより、相手が知っていそうなものを前提に三案ほど出させると選びやすくなります。

図を作る前なら、矢印を文字で並べた案も頼めます。たとえば「申請者が入力する → 経理が確認する → 上司が承認する」のように書き出せば、箱の数や矢印の向きを決める前に流れの抜けを見つけられます。

新人、他部署、上司向けに同じ事実を言い換えることもできます。AIへの依頼で役割を指定しないと、誰にでも当たり障りのない説明になりがちです。報告の材料が散らかっているときは、[5W1HをAIで報告に使う方法](/ai-jitan-lab/gyomu-jitan/5w1h-ai-houkoku/)で、確認済みの事実と判断してほしいことを先に分けます。

## 人が確かめるところ

AIの出力をそのまま説明に使う前に、たとえが合わない部分を見ます。たとえが分かりやすくても、肝心の例外や担当の違いが消えていたら使えません。

数字は元の記録に戻って確かめます。「二日短縮できる」「三割減る」のような数字を、材料なしにAIが足したなら削除します。相手が本当に知らない言葉も、人にしか判断できません。新人だから分からないと決めつけず、初日に何を説明したか、普段どの資料を見ているかを確認します。

説明の順番を整えたいだけなら、[PREP法をAIで下書きする例文](/ai-jitan-lab/gyomu-jitan/prep-hou-ai-reibun/)も使えます。ここで紹介した表や図解は、その型を説明するものではなく、話す対象と相手に合わせて材料を選ぶためのものです。

## コピーして使えるプロンプト

下の`[ ]`を、入力してよい範囲の情報に置き換えて使ってください。社外秘、取引先名、個人情報を入力する前に、会社の規程を確認します。

```text
次の内容を、[相手]に説明するための下書きにしてください。

【相手】
[新人 / 他部署 / 上司。相手がすでに知っていること]

【説明したいもの】
[仕組み / 手順 / 理由 / 数字 / 比較 / 変更点]

【確認済みの事実】
[事実、数字、担当、期限]

【相手にしてほしいこと】
[理解してほしいこと、判断してほしいこと]

【ルール】
- 説明したいものに合う見せ方を一つ選び、その理由を書く
- たとえを3案、図にする前の矢印の文字版を1案、相手向けの言い換えを1案出す
- 材料にない数字、期限、担当、理由を足さない
- 分からない言葉や確認が必要な点は、推測せず[確認が必要]と書く
- たとえが合わない部分も最後に書く
```

## 新人への説明例

架空の「東町印刷」で、新人の佐藤さんが受注一覧を更新する場面です。先輩は、一覧に入力する順番を説明したいのに、画面にある項目を上から全部読んでしまいました。佐藤さんは、どこから始めればよいか分かりません。

ここでは手順が対象です。先輩は、見積書を受け取る、一覧に案件名を入れる、納期を確認する、担当者に知らせる、の順に四つだけ並べます。赤い必須項目がどれかを説明するのは、その後です。画面全体の図より、作業を始める順番のほうが役に立ちます。

AIには、この四つの手順から矢印の文字版を作らせられます。ただし、納期を誰に確認するかは会社ごとに違います。先輩が決めずにAIへ任せる部分ではありません。

## 上司への変更説明例

架空の「南口配送」で、配車担当が締切時刻の変更を部長へ説明する場面です。担当者が話したいのは新しい入力画面の細部ですが、部長が知りたいのは、翌日配送の受付にどんな影響が出るかです。

そこで担当者は、変更前と変更後を表にします。変更前は17時までの入力、変更後は16時30分までの入力。理由として確認済みなのは、17時から配送順の確定作業を始めることです。部長には、取引先への案内をいつ出すか判断してほしいと伝えます。

ここで「30分早まる」を「配送順を確定する作業に30分の余裕ができる」と言い換えると、数字の意味が伝わります。余裕が十分か、案内の対象がどこまでかは、担当者と部長が実際の予定を見て決めます。

説明する対象と相手から見せ方を選ぶ早見表は、拙著『説明力、結局どれをいつ使えばいいか』にまとめています。 [Amazonで見る](https://www.amazon.co.jp/dp/B0HQB7G1HL)

## まとめ

わかりやすい説明は、話を短くするだけでは作れません。仕組み、手順、理由、数字、比較、変更点のどれを伝えるのかを決め、相手の前提に合わせて見せ方を選びます。

AIは、たとえ、矢印の文字版、相手別の言い換えを出す役に向きます。たとえのずれ、数字、相手が知らない言葉は、人が確かめてから使ってください。
