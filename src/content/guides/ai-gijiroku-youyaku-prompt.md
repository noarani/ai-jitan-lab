会議の文字起こしをChatGPTで短くしても、次に誰が何をするかが曖昧なら、会議後の作業は進めにくくなります。要約では、発言をきれいにまとめることより、依頼された作業、担当、期限、未決の点を分けて残すことが重要です。

この記事では、確認済みの文字起こしまたは会議メモから、会議後のタスクを残す要約下書きを作るプロンプトと確認手順を扱います。例はすべて架空で、実在の会社・人・数値は使いません。議事録全体の見出しや決定事項の整理には、[AI議事録作成プロンプト](/ai-jitan-lab/ai-gijiroku/ai-gijiroku-sakusei-prompt/)も参照してください。

## 文字起こしは、どう整えてから要約しますか？

**結論：人名・数字・期限・否定表現を原記録と照合し、確認できない箇所を残してから要約に渡します。**

文字起こしに誤りがあるまま要約すると、存在しないタスクや別の期限が、もっともらしい文章で残ることがあります。まず、会議の目的、参加者、会議日を添えます。次に、依頼や約束に当たる発言、日付、担当を表す箇所を確認します。

とくに「今回は実施しない」「持ち帰って確認する」のような否定や保留の表現は、タスクと取り違えないようにします。聞き取れない語、発言者、期限は補わず、`[聞き取り不明]`または`[要確認]`と記します。人名・数字・否定表現を確認する順番は、[AI議事録の文字起こしを確認する方法](/ai-jitan-lab/ai-gijiroku/ai-gijiroku-mojiokoshi-kakunin/)で詳しく説明しています。

AIへ入力する前に、会議内容を渡してよい範囲も確認してください。顧客名や個人情報などを含む場合は、勤務先のルールと利用するサービスの扱いに従い、必要なら入力対象から外します。要約用の材料は、確認済みの範囲だけを選びます。

## タスクを残す要約プロンプトは、どう書きますか？

**結論：タスク・未決事項・確認が必要な箇所を別に出力させ、担当や期限を推測しないよう先に指示します。**

会議後のフォローアップでは、会話の要点を一段落に圧縮するより、後で確認・実行できる欄を作る方が役立ちます。次のテンプレートは、タスクを抽出しつつ、不明なことを不明のまま残すための下書き用です。

```text
以下の会議メモまたは確認済みの文字起こしを要約してください。
会議後のフォローアップ用の下書きであり、原文にない内容は補いません。

【会議情報】
- 会議名：［会議名］
- 日時：［日時］
- 参加者：［参加者］
- 目的：［会議の目的］

【守ること】
- 明確に依頼・合意・担当が示された内容だけをタスクとして抽出する。
- 担当、期限、作業内容のどれかが不明なら、推測せず [要確認] と書く。
- 検討中、保留、確認待ちの内容を、決定済みやタスクとして書き換えない。
- 発言者が不明な箇所を特定の人へ結び付けない。
- 原文と照合が必要な箇所は、削除せずに残す。

【出力形式】
1. 会議の要点（3項目以内）
2. 会議後のタスク（担当｜期限｜内容｜根拠または確認状態）
3. 未決事項（論点｜次に確認する人または場｜状態）
4. 参加者に確認すること

【会議メモまたは文字起こし】
［ここに貼り付ける］
```

出力の「根拠または確認状態」には、たとえば「担当者の発言で依頼」「期限は`[要確認]`」のように、確定できた範囲を残します。AIの文章が自然でも、会議で依頼された根拠まで確認できたことにはなりません。

## タスクは、どのように抜け漏れなく確認しますか？

**結論：一つのタスクを「担当・期限・内容・確認状態」に分け、空欄を完成したように扱わないことが大切です。**

AIが「資料を準備する」とまとめた場合でも、誰が何の資料を、いつまでに、どこへ出すのかは別に確認します。表のように読む順番を固定すると、要約の文章だけを読んだときの見落としを減らせます。

| 確認する項目 | 見る内容 |
| --- | --- |
| 担当 | 本人が引き受けたか、依頼先が明確か |
| 期限 | 会議で決まった日付か、後で決めるのか |
| 内容 | 成果物や次の行動が具体的に分かるか |
| 確認状態 | 原記録で確認済みか、参加者へ確認待ちか |

会話の中で案として出ただけの作業は、タスクにしません。「確認しておく」「検討する」といった表現も、担当や対象が分からなければ`[要確認]`として残します。期限がないからといって、AIに一般的な期日を入れさせないようにします。

要約後は、元の記録に戻り、タスク欄の各行に対応する発言を見ます。タスクを多く拾うことより、確かめられない内容を確定扱いにしないことが優先です。会議録を作成して共有する全体の流れは、[AI議事録の作り方：録音から確認・共有までの4ステップ](/ai-jitan-lab/ai-gijiroku/ai-gijiroku-4step-nagare/)で確認できます。

## 未決事項は、どのように残しますか？

**結論：決定していない理由と次の確認先を併記し、決定事項やタスクの欄に混ぜないようにします。**

会議では、選択肢を比較しただけで結論が出ないことがあります。要約で未決事項を省くと、あとから「決まっていたはず」と受け取られるおそれがあります。一方で、未決の論点をタスクとして断定すると、担当者が決まっていない作業まで割り当てたように見えます。

未決事項は、「論点：提案書の範囲」「状態：案を比較中」「次に確認する人または場：次回会議で確認」のように分けます。原記録に確認先がなければ、無理に担当を置かず`[要確認]`と記します。確認が終わるまでは、未決欄を消して文章を整えません。

決定事項、タスク、未決事項を別にしておくと、参加者は自分が実行することと、次に判断することを区別しやすくなります。会議後に追加の連絡が必要な場合も、何を確認するための連絡なのかを示せます。

## 参加者には、何を確認してから共有しますか？

**結論：タスクの担当・期限・内容と、未決事項の状態を参加者へ確認し、確認済みでない箇所を明示して共有します。**

共有前には、タスクの各行について、担当と期限が会議で合意されたものかを確認します。会議中に決めていない場合は、参加者へ候補を送るのではなく、「担当と期限は`[要確認]`」と分かる形で確認します。確認依頼そのものを、AIが決めた割り当てとして扱いません。

確認する相手は、会議の運用に合わせて参加者、進行役、記録責任者などから決めます。返信がない状態を承認とみなすかどうかも、この記事では判断しません。勤務先のルールや会議ごとの合意に従ってください。

確認後は、更新した日付と確認者を必要な範囲で残し、共有先が適切かを見直してから配布します。録音の可否、同意の要否、原記録の保存期間、議事録の法的効力は、この記事だけでは判断しません。
